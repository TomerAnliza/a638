# סוליטייר (Solitaire)

> **מטרת הפרויקט:** משחק סוליטייר קלאסי (Klondike) שרץ בדפדפן, בנוי ב-Next.js ללא שרת. פרויקט לימודי לעבודה עם מספר סוכני AI במתודולוגיית SDD. הצלחה: משחק שלם שאפשר לנצח בו, עם לוגיקה מכוסה בבדיקות

## מתודולוגיה: SDD (Spec-Driven Development)

הפרויקט מנוהל לפי **פיתוח מונחה-מפרט**. העיקרון: **המפרט קודם לקוד.**
אף שורת קוד לא נכתבת לפני שיש מפרט מאושר שמגדיר מה היא אמורה לעשות.

הזרימה, לכל יכולת (feature):

```text
1. SPEC      specs/NN-feature-name/spec.md    — מה בונים ולמה. דרישות, קריטריוני קבלה
2. PLAN      specs/NN-feature-name/plan.md    — איך בונים. ארכיטקטורה, קבצים, החלטות
3. TASKS     specs/NN-feature-name/tasks.md   — משימות קטנות, ממוספרות, עם תוצר ברור
4. IMPLEMENT src/ + tests/                   — קוד שממש את המשימות, אחת-אחת
5. VERIFY    בדיקות עוברות + המפרט מסומן כמומש
```

כללים שאינם ניתנים למיקוח:

- **המפרט הוא מקור האמת.** כשהקוד והמפרט סותרים, מתקנים את אחד מהם במפורש — לא מתעלמים
- **שינוי דרישה מתחיל במפרט**, לא בקוד
- **כל משימה ב-`tasks.md` קטנה מספיק** כדי שסוכן אחד יסיים אותה בסשן אחד
- **קריטריוני קבלה ניתנים לבדיקה.** "עובד טוב" אינו קריטריון; "מחזיר 200 עם JSON תקין" כן

## עבודה עם סוכנים

הפרויקט בנוי לעבודה של **כמה סוכני AI במקביל**. ההוראות אינן נשארות בצ׳אט —
הן נשמרות בקבצים, כדי שכל סוכן, בכל סשן, יתחיל מאותו מקום:

- **`AGENTS.md`** — מי עושה מה, ומה אסור. קראו אותו לפני כל משימה
- **`CLAUDE.md`** — נטען אוטומטית ל-Claude Code. מפנה ל-`AGENTS.md` ול-`specs/`
- **`docs/journal/`** — כל פעולה משמעותית מתועדת, כדי שהסוכן הבא ידע מה קרה

## איך מריצים

דרישה מוקדמת: Node.js 20 ומעלה (נבדק עם Node 26.8.2 ו-npm 11.19.1).

```bash
npm install        # התקנת תלויות
npm run dev        # שרת פיתוח
```

כשזה עובד, הטרמינל מציג `▲ Next.js 16.4.2 (Turbopack)` ואת הכתובת
`http://localhost:3000`. בדפדפן מופיע לוח ירוק עם כותרת «סוליטייר», ערימת משיכה
כחולה, ארבע משבצות יסוד עם האות A, ושבע עמודות קלפים באורכים 1 עד 7.
לחיצה על ערימת המשיכה מציגה קלף ב-waste והמונה עולה ל-1.

```bash
npm test           # 34 בדיקות של לוגיקת המשחק (Vitest)
npm run lint       # ESLint
npm run build      # בנייה לייצור
```

### חיבור ל-Supabase

הפרויקט מחובר לפרויקט `solitaire` ב-Supabase (מפרט 02). כרגע תשתית בלבד, ללא טבלאות.

```bash
cp .env.example .env.local   # ולמלא את שני הערכים מחלון Connect בלוח הבקרה
npm run supabase:check       # מדפיס: חיבור ל-<host>: סטטוס 200 (Auth vX.Y.Z)
```

הלקוח ב-`src/lib/supabase/client.ts` נוצר בעצלות דרך `getSupabaseClient()`.
רק המפתח הציבורי (publishable) נכנס לפרויקט. המפתח הסודי — לעולם לא.

### איך משחקים

לחיצה על קלף גלוי בוחרת אותו (ב-tableau — אותו ואת כל הקלפים שמתחתיו, מסומנים
בצהוב). לחיצה על ערימת היעד מבצעת את המהלך. מהלך לא חוקי מבטל את הבחירה בשקט.
לחיצה על ערימת המשיכה מושכת קלף; כשהיא ריקה, לחיצה מחזירה את כל ה-waste.

## איפה מתחילים

1. קראו את `AGENTS.md`
2. פתחו את `specs/` ומצאו את המפרט הפעיל (סטטוס `in-progress`)
3. בחרו משימה פתוחה מ-`tasks.md` של אותו מפרט
4. בסיום — עדכנו את `tasks.md` ואת `docs/journal/`
