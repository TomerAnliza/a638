## הבעיה

המשחק רץ כולו בדפדפן ואינו זוכר דבר. כל יכולת עתידית ששומרת מצב — ניקוד,
משחק שמור, לוח תוצאות — צריכה בסיס נתונים. מפרט זה מחבר את הפרויקט ל-Supabase
**בלי להחליט עדיין מה נשמר**. זה מפרט תשתית.

## מה בונים

- חבילת `@supabase/supabase-js` מותקנת
- קובץ `.env.local` (מחוץ לגיט) עם כתובת הפרויקט והמפתח הציבורי. `.env.example`
  בגיט עם השמות בלבד, ללא ערכים
- לקוח דפדפן ב-`src/lib/supabase/client.ts` שנוצר ממשתני הסביבה
- סקריפט `npm run supabase:check` שפונה ל-REST של הפרויקט ומדפיס אם החיבור תקין

## מחוץ לתחום

- סכמה, טבלאות, RLS
- התחברות משתמשים (Auth)
- שמירת משחקים או ניקוד — יוגדר במפרט נפרד
- מפתח service role. רק המפתח הציבורי (anon / publishable) נכנס לפרויקט

## קריטריוני קבלה

1. `git status` אינו מציג את `.env.local`, ו-`git ls-files` אינו כולל אותו
2. `.env.example` קיים בגיט עם שמות המשתנים בלבד
3. `npm run supabase:check` מדפיס סטטוס 200 מול `/auth/v1/health` של הפרויקט.
   **תיקון מ-20 באוקטובר 2026:** במקור נכתב `/rest/v1/`, אך שורש ה-REST דורש מפתח
   סודי במערכת המפתחות החדשה ומחזיר 401 למפתח ציבורי. הבדיקה הוחלפה לנקודת health של Auth
4. `npm run build` ו-`npm run lint` עוברים עם הלקוח החדש בקוד
5. אף מפתח אינו מופיע בקוד, ביומן או בפלט של סקריפט

## מקורות

- תשובת השרת עצמו ל-`GET /rest/v1/` עם מפתח ציבורי: `401 Secret API key required`.
  נבדק ב-20 באוקטובר 2026 עם curl
- לוח הבקרה של Supabase, חלון Connect של הפרויקט — שמות משתני הסביבה והקטע
  ל-Next.js. נבדק ב-20 באוקטובר 2026
